# Mobile 1.2.0 candidate

This is source preparation, not a store release declaration. The candidate uses
native version `1.2.0` and an `appVersion` runtime boundary separate from older
`1.1.1` binaries. EAS production owns and increments store build numbers remotely.
No release tag, build, upload or public promotion is created by this change.

## Included source changes

- New production and preview binaries use only embedded code/assets, with Expo
  OTA requests disabled. Code fixes arrive through installed/store-delivered
  binaries. Already-installed older builds retain their previous behavior until
  users update; no wire-level privacy proof is implied by configuration checks.
- Query caches and mounted native-surface leases end when an account signs out
  or the active server/account changes.
- Durable financial data and queued mutations are partitioned by authenticated
  account, server and bill group. Qualified same-account offline work survives
  sign-out; another account cannot read or replay it.
- Earlier local data has no trustworthy row owner and stays encrypted in
  quarantine. Reconnect to download current account data. Earlier unsynced work
  requires owner-verified recovery and remains visibly unsynchronized. Do not
  uninstall the app or clear its data before recovery.
- Unknown legacy credential ownership requires live verification or sign-in;
  matching, already-qualified accounts retain offline access.
- Compatible Expo 58 / React Native 0.88 patch dependencies are aligned. Source
  validation includes real SQLite isolation/migration regressions and mounted
  session/recovery UI tests.

Android retains subscription/usage status without upgrade, checkout or portal
links. The existing iOS purchase path remains scoped to the initial US release.
Settlement actions report partial failures, remain bound to the active screen
and account, and preserve retry identities. Guarded Mark Paid additionally
requires advertised server support, the original share and bill versions, and
the exact due occurrence; an older server stays readable but cannot receive an unsafe
payment toggle. A conflict requires fresh server state and explicit review
before a new intent.

## Required candidate evidence

Keep the [mandatory release gates](../implementation-status.md#mandatory-release-gates)
open until they have evidence from the actual candidate:

- Clean install and source checks, signed Android/iOS builds, actual store build
  numbers, source revision and uploaded telemetry artifacts.
- Upgrade an existing installation without uninstalling or clearing app data.
  Confirm a strictly increasing store build number, quarantine notice, preserved
  earlier queued work, explicit reconnect, and no automatic unowned replay.
- Two-account same-server/same-group offline, reconnect, logout/relogin, delayed
  response, background sync and reminder-action tests. Preserve each account's
  qualified work across process death.
- Verify actual packaged update flags and startup/crash/relaunch traffic: the
  new binary must not contact the Expo Update endpoint.
- Real-device notification/passkey/widget, accessibility and native telemetry
  privacy/symbolication acceptance. A simulator or source test alone does not
  close the physical iOS gate.
- Current Apple/Play privacy declarations, review access, availability scope and
  platform-specific review/testing eligibility. Initial iOS availability is US-only.

Record current evidence and unresolved gates in implementation status; do not
reuse historical `1.1.1` build acceptance as `1.2.0` proof.
