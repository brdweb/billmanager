# BillManager v4.13.1

## Changes

- Fixed Stripe webhook processing: 4.13.0 called `.get()` on `stripe.Event`
  / `Subscription` SDK objects, so every verified webhook returned 500 and
  checkout completion, renewals, cancellations, and plan changes were never
  applied. SDK objects are now converted with `to_dict()` at the boundary and
  billing periods are read from subscription items (API `2025-03-31.basil`+).
- Migrated Checkout Session creation to Stripe 16 / API `2026-09-30.endive`:
  `allowed_payment_method_types` replaces the removed `payment_method_types`
  and keeps checkout card-only.
- Refreshed server dependencies: stripe 16.0.0, resend 2.49.1, PyJWT 2.15.1,
  sentry-sdk 2.71.0, webauthn 3.0.1, Werkzeug 3.1.9.
- Refreshed web dependencies: Mantine 9.7.1, Tabler icons 3.49.0, i18next
  26.4.3 / react-i18next 17.0.16, Vite 8.3.4, Playwright 1.64.0, Vitest
  coverage 5.0.3, ESLint 10.12.0, jsdom 30.1.2, swagger-ui-dist 5.33.1.

## Upgrade notes

- No configuration or schema changes.
- Billing-enabled deployments: after upgrading, open Stripe Dashboard →
  Developers → Webhooks and review failed deliveries from the 4.13.0 window.
  Stripe retries for up to 3 days; older events need a manual resend or
  subscription reconciliation.
