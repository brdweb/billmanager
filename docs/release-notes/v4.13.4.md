# BillManager v4.13.4

## Changes

- Disclose Pro auto-renewal on the web Billing page directly above **Get Pro**:
  the price ($2.99 per month or $24.00 per year), that it is charged when you
  subscribe and renews automatically until canceled, and that cancellation is
  available through Manage Subscription in the billing portal. Subscribing
  links to the Terms of Service and Privacy Policy. The trial footer no longer
  implies that a purchase includes a trial: new accounts start with a 30-day
  free trial, and subscribing during the trial ends it and starts paid billing
  right away.
- Confirm checkout returns. `/billing/success?session_id=…` shows that payment
  was received and polls `/billing/status` (bounded, about 60 seconds) until the
  subscription is active on Pro. If activation takes longer, the page says no
  second checkout is needed and offers **Refresh status**. `/billing/cancel`
  confirms that nothing was charged and the plan is unchanged.
- Treat a `pending` subscription row left by a canceled first checkout as Free,
  so the Billing page no longer shows a raw pending plan and **Get Pro** stays
  available.
- Resolve the subscription for invoice events from
  `parent.subscription_details.subscription`, where Stripe API
  2025-03-31.basil and later place it, as well as the top-level `subscription`
  field. `invoice.paid` now refreshes the billing period and stores the status
  Stripe reports, and `invoice.payment_failed` sets `past_due`. Previously
  these modern invoice events were acknowledged without effect.
- Ignore invoice events for a subscription already recorded as `canceled` or
  `incomplete_expired` (the event ledger and ordering watermark still update),
  so a leftover invoice paid or failed after cancellation cannot reopen it or
  block resubscribing.
- Allow returning customers to resubscribe. A completed checkout replaces the
  stored subscription only when the previous one is terminal both locally and
  at Stripe and the checkout customer matches the stored customer. Previously a
  returning customer was charged and the webhook failed with a conflict.
- `POST /billing/create-checkout` returns `400` and directs the user to the
  billing portal while the stored subscription is not terminal (for example
  `past_due`, `unpaid`, `incomplete` or `paused`), instead of creating a
  second subscription.
- Security: `joserfc` 1.7.5 → 1.7.7 (CVE-2026-119284), `pyasn1` 0.6.4 → 0.6.5
  (CVE-2026-119194, CVE-2026-119195, CVE-2026-119196, CVE-2026-119197), and
  web `follow-redirects` 1.16.1 → 1.16.2 (GHSA-mrwp-f3q8-3g9p).
- Dependency refresh: `stripe` 16.0.0 → 16.1.0, `resend` 2.50.0 → 2.50.1,
  `pytest` 9.2.0, Mantine 9.7.4, axios 1.21.0, react-router 8.5.1, i18next and
  react-i18next patch releases, eslint 10.14.0, swagger-ui-dist 5.34.1, and the
  frontend build image `node:24.22.2-slim`.

## Upgrade notes

- **No database migration.** `apps/server/db_migrations.py`,
  `apps/server/migration.py` and `apps/server/models.py` are unchanged since
  4.13.3 (`81a9e78`), and no other server change adds schema DDL. No migration
  runs at startup for this release.
- No new configuration or environment variables are required. Billing
  readiness still requires the Stripe SDK, API key, webhook secret, and the two
  Pro prices (`STRIPE_PRICE_PRO_MONTHLY`, `STRIPE_PRICE_PRO_ANNUAL`); Basic/Plus
  price variables remain optional aliases. The documentation now states this
  correctly.
- Resubscription calls `stripe.Subscription.retrieve` for the previous
  subscription. If the configured key is a restricted key, it needs read access
  to subscriptions; a failed retrieve returns `500` so Stripe retries.
- External API consumers of `POST /billing/create-checkout` may now receive
  `400` for an account whose stored Stripe subscription is not terminal. `400`
  was already in
  the published schema; the OpenAPI contract is otherwise unchanged apart from
  its version.
- After deployment, review failed `invoice.*` and `checkout.session.completed`
  deliveries in the Stripe Dashboard. See `docs/stripe-webhook-operations.md`
  for the replacement rules and when a resend is safe.
- This is the web/server release lane. Mobile-only changes merged in this
  period (Android layout and build-memory fixes, iOS capture tooling, mobile
  dependency updates) require a separate signed mobile build and store review.
  This release does not establish mobile store availability.
