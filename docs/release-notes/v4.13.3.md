# BillManager v4.13.3

## Changes

- Return account ownership consistently after password, OAuth, password-change,
  and two-factor sign-in. Managed users no longer see owner-only administration
  or whole-account deletion controls.
- Clear old bills immediately when changing accounts or bill groups and ignore
  obsolete asynchronous responses, including requests delayed by auto-payment
  processing.
- Recover the signed-in session when the saved bill group was removed or its
  access was revoked. Identity/preferences requests remain available, and the
  web app persists an accessible replacement group. Financial endpoints continue
  to reject inaccessible groups.
- Correct the existing `/billing/change-plan` response: item changes take effect
  immediately, without a deferred schedule. Local tier and interval now update
  after provider success; provider failures retain the original local plan.
  The Stripe request parameters, proration policy, discounts, and trial/renewal
  settings are unchanged.
- Display release-note dates as the intended calendar day in every time zone.
- Patch msgpack from 1.2.2 to 1.2.4 for CVE-2026-114613.

- Advertise guarded settlement payments to compatible clients. Version and due
  date checks run under bill/share locks, so a stale Mark paid action cannot
  undo a payment or pay a different recurrence. Completed idempotent retries
  still replay; callers omitting the new occurrence field retain legacy toggles.
- Accept an explicit paid or unpaid intent on guarded settlement payments and
  advertise it as `settlement_payment_desired_state`. A retry after a lost
  response replays the original result instead of toggling it back; a request
  whose state already matches returns a conflict. Callers omitting the field keep
  the earlier behavior.
- Keep the original request identity, versions, due date and intent when the web
  Settlements and bill list retry a shared payment. Duplicate clicks and late
  callbacks from a previous account, group, bill or view are ignored, and a
  conflict requires a fresh read before a new action.
- Report `can_manage_subscription` in billing status, true only for the SaaS
  account owner with a stored provider customer and a configured billing
  portal. The web app shows Manage subscription only when it is true, so locally
  granted Pro accounts keep their access without a portal action that would fail.

## Upgrade notes

- No server schema migration or new configuration is required.
- External API consumers of `/billing/change-plan` now receive the accurate
  `effective: immediately` value instead of the misleading period-end message.
  This corrects the description of the existing provider update behavior.
- This is the web/server release lane. Native account-isolation and purchase-flow
  improvements require a separate signed mobile build, installed acceptance,
  and store review. This release does not establish mobile store availability.
